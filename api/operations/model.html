    signalwire.operations.model¶

    signalwire.operations.model ¶

    Copyright (c) 2025 SignalWire

    This file is part of the SignalWire SDK.

    Licensed under the MIT License. See LICENSE file in the project root for full license information.

    What a developer writes for an operations agent: an operation's fields, the change its prepare builds, the writes that carry it out, and the two ways prepare says no (Need, Refuse).

    NOT_SAID = 'not said' module-attribute ¶

    The value a field takes when the caller hasn't said it: the model's honest answer, which the operation treats as missing rather than as a value.

    __all__ = ['NOT_SAID', 'Change', 'Field', 'Need', 'Operation', 'Refuse', 'Values', 'Write', 'WriteFailed'] module-attribute ¶

    Need ¶

    Bases: Exception

    Raised by prepare when something the operation needs wasn't said.

    Nothing is proposed. The model is told what to ask, and keeps everything the caller already gave for the next call.

    Example

    if not fields.size: raise Need("Which size would they like: small, medium or large?", ["size"])

    Refuse ¶

    Bases: Exception

    Raised by prepare (or a lookup) when the request breaks a rule.

    Nothing changes. The model is told why, and what can be done instead.

    Example

    if order.status != "pending": raise Refuse("Only pending orders can be cancelled.", "Offer a return once it's delivered.")

    WriteFailed ¶

    Bases: Exception

    Raised by apply when a backend write was refused.

    The change stops at that write: the writes before it stay made, and the model is told exactly what went through.

    Write ¶

    One backend write a change carries out, kept as data.

    A change's writes are frozen when it is read back: a later amendment builds a new change, and never edits these.

    Example

    Write("cancel_pending_order", order_id="#W1234567", reason="no longer needed")

    Change dataclass ¶

    A change prepare built, ready to read back.

    Example

    Change( read_back="Cancel order #W1234567, refunding $54.04 to the card it was paid with. Shall I go ahead?", touches=["order:#W1234567"], writes=[Write("cancel_pending_order", order_id="#W1234567", reason="no longer needed")], money=[-54.04], currency="USD", done=["Order #W1234567 is cancelled; $54.04 goes back to the card."], )

    read_back instance-attribute ¶

    The words the platform says, and the caller says yes to. The change itself goes in the first clause: a read-back cut off by the caller's answer is judged on what they heard.

    touches = () class-attribute instance-attribute ¶

    Stable keys for everything it acts on, such as order:#W1234567 or item:9494281769. A new request is weighed against the change waiting by these.

    writes = () class-attribute instance-attribute ¶

    The backend writes, in order.

    money = None class-attribute instance-attribute ¶

    The money each write moves: more than 0 charged, less than 0 back to the caller, as a number, a numeric string or a Decimal. Kept exactly in the call's record, for totals.

    currency = None class-attribute instance-attribute ¶

    The ISO 4217 code of that money, such as "EUR"; defaults to the service's currency. Totals are kept for each currency apart.

    done = None class-attribute instance-attribute ¶

    What to tell the caller once each write went through, one per write, or one sentence for the whole change.

    after = None class-attribute instance-attribute ¶

    The kind of another change the caller asked for that has to go first, such as "address" for an item change that would leave the order's address unchangeable. This one isn't read back yet: it's set aside, the model is told to call that kind's tool now, and it's offered once a change of that kind is settled.

    after_why = '' class-attribute instance-attribute ¶

    Why the other change goes first, in a clause: "an order's items change last, since after that nothing else in it can change".

    then = None class-attribute instance-attribute ¶

    What the model is told to do once it's made, in place of everything the service would tell it ("Tell them it's done", and what's next): for a change whose effect comes after the tool's result, such as a payment the platform takes next. None: the service's words.

    __init__(read_back, touches=(), writes=(), money=None, currency=None, done=None, after=None, after_why='', then=None) ¶

    Field dataclass ¶

    One thing an operation (or a lookup) takes from the caller.

    Example

    reason = Field(Literal["no longer needed", "ordered by mistake"], "Why, in their words", ask="Why are they cancelling it?")

    The value's type: str, int, float, bool, a Literal, list[...], dict[str, ...], a TypedDict, or a JSON schema dict.

    description instance-attribute ¶

    What it is, in the caller's terms. The model reads it.

    required = True class-attribute instance-attribute ¶

    Whether the operation needs it.

    ask = None class-attribute instance-attribute ¶

    The question for the caller when it's missing. With it, a required field the model sends empty, null or as "not said" (a choice of values gets that option) is asked for before prepare runs, so the model is never pushed to invent it.

    Values ¶

    An operation's fields as the model gave them: values.order_id.

    A field that wasn't given (or came as null or "not said") is None. values.args holds the arguments as they came.

    Operation ¶

    Something the agent can change for a caller.

    Subclass it, declare its Field attributes, give it a docstring (what it does, as the model reads it), and write prepare. Register it with ServiceAgent.operation.

    Example

    @agent.operation(tool="cancel_order") class Cancel(Operation): '''Cancel pending orders.''' order_ids = Field(list[str], "The orders to cancel")

    def prepare(self, call, f):
    ...
    return Change(read_back=..., touches=..., writes=...)

    kind = '' class-attribute ¶

    Its name in the call's record and in confirm_change: the class name in lower case unless set.

    tool = '' class-attribute ¶

    The tool's name. Use the verb a caller would use.

    combine = None class-attribute ¶

    When a request of this operation made "as well" merges into one of the same operation waiting for its yes: the fields that must be the same in both (such as where a refund goes). None: they are never merged.

    goes_before = () class-attribute ¶

    Kinds of change that must wait for this one when both are for the same things (an address change before an item change).

    guidance = None class-attribute ¶

    Instructions for a step of its own, entered when its prepare raises Need. None: no step of its own.

    fillers = () class-attribute ¶

    Short phrases said while its tool runs: a list, for every language, or lists by language code.

    confirm = True class-attribute ¶

    False for a change that goes through without a read-back and a yes, such as a move in a game. Its writes run when its tool is called.

    before_identity = False class-attribute ¶

    True for an operation a caller can use before they're identified, such as booking for a new customer.

    ask_in_order = False class-attribute ¶

    True to ask for one missing field at a time, in declaration order.

    offered_in = None class-attribute ¶

    The steps that offer its tool, by name; None for every step, so a caller who asks for it anywhere is never stranded.

    secure = True class-attribute ¶

    Whether its tool takes the agent's per-call security token.

    fields() ¶

    The operation's fields, in declaration order.

    prepare(call, values) ¶

    Check the request and build its change.

    Returns a Change, or raises Need or Refuse. It may look things up, and may be async, but never writes.

    apply(call, write) ¶

    Carry out one write; raise WriteFailed if the backend refuses it.

    Defaults to the service's writer (Operations.writes_with). May be async.

    merge(held, new) ¶

    One request from the change waiting (held) and a request made as well (new). Lists are joined, and an item asked for again goes as asked now (same_item); other fields take the new value.

    same_item(field, a, b) ¶

    Whether two entries of a list field are the same thing asked for twice.

    What it does, as the model reads it: its docstring's first paragraph.
